# Lin 预填充助手

SillyTavern 前端扩展，v1.3.0。用于 Lin 2.8.2 的 assistant 承接和末尾 user 确认。支持识别 Gemini 4 Carbon、Hydrogen 和 Argon；不需要油猴脚本。

## 在 Vertex 上使用

覆盖酒馆主机上已有的扩展目录，确保 `manifest.json` 与 `index.js` 位于该目录第一层。不要同时保留两份。刷新后打开「Lin 预填充助手」→「请求处理」→ **Vertex 正文承接（Lin 2.8.2）**。升级保留原选择；仍选「原样诊断」就只观察，文字和参数一项都不会动。

- 正常聊天、滑动和重生成时，核对启用的 Lin 条目标识、角色、完整文本和当前位置。把原确认中的执行细则放到原 assistant 承接之前。保留规则的 user 身份和原承接的 assistant 身份；最后用一句短 user 确认收尾。只在本次请求中去掉原确认里能逐字核实的“最大程度思考”段，保留其他条目、栏目、格式和篇幅；不额外催写，不限制 CoT 字数。
- 默认沿用输出上限。若已见到 `MAX_TOKENS`，可以单独勾选「16,384 → 32,768」。仅在正文承接确实生效且原值恰为 16,384 时改本次请求；不会降低其他上限，不修改全局预设。实际用量、耗时和费用可能增加。服务端如何分配思考与正文仍由模型和后端决定。
- 未找到唯一承接、遇到未识别的中间消息、自定义连接、别名、工具、结构化输出、继续生成等情形，不强行套用正文承接。需要时退回普通兼容行为；诊断显示实际执行结果。功能不发送新的请求。此方法只让语义更接近预填充，不能指定模型已经写出的首字。
- 面板历史显示浏览器最终核对的三段顺序、请求预算、结束原因。Google 单独报告的候选和思考 token 才按对应口径展示。少量重复文本加 `[DONE]` 而没有结束原因时，查看那条回复的原始文本；不能据此认定审核或预算耗尽。

## 安装与测试

服务器解压覆盖原扩展或从部署的 Git 仓库更新。无需重新导入预设。Node 20+ 可运行 `npm test`；部分旧版专用测试需要另行指定历史样本，本仓库不含私人聊天或预设。离线组合检查覆盖两种扩展加载顺序、角色转换和可选预算；未连接付费模型。

## 1.2.9 异常处理

- HTTP 200 中携带的上游 503、明确限制或拒绝字段，优先于后续客户端中止显示。停止事件本身无法证明用户点过停止按钮。
- 已关联请求报错且未确认收到模型文本时，手动补全入口不再接写占位或错误提示；处理连接问题后仍可手动重生成。报错前已有模型文本时，仍可自行判断是否继续。普通文字中的道歉不等于接口限制。
- Gemini 4 在原样诊断、旧版增强、承接兼容三种模式下均识别 `CONTINUATION`，普通“继续”不能替代服务商凭据续传。
- 历史详情显示实际发送参数中的 AI Studio / Vertex / 自定义连接来源。升级保留旧记录的原版本和模式；旧记录不能用于证明新版本已经发送成功。

这次修复处理异常诊断与手动操作，不承诺消除模型拒答或服务商限制。反复出现的短回复若没有错误字段和结束原因，仍标记为原因未知；可用面板的“复制当前回复原文（含注释）”核对内容。插件不自动追加请求。

## 普通「承接兼容」怎么处理

- 普通回复、重生成、滑动重生成：按实际启用顺序核对 Lin 的 assistant 承接与 user 确认。顺序正确时保持请求原样。若本应在确认之前的独立承接误放为最后一条非空消息，且能唯一确认两个条目与中间的预设部分，只移动这一条原消息。其余消息保持原顺序。没有增加或删除字符。
- 条目禁用、生成触发条件不匹配、匹配不唯一、条目被合并或尾部属于别的回答时，不猜测、不拆消息。普通“继续”交给酒馆。工具、结构化输出及已有预填充不叠加。不会更改预设、聊天、停止词、思考配置或 token 上限。
- 支持酒馆的 AI Studio、Vertex 和匹配模型名的自定义聊天连接。别名只能用来选取兼容行为，不能验证实际模型与中转的参数。面板的“本地自检”核对当前配置，不调用模型；实际发送后可以查看承接和确认的相对位置。发送核对只到浏览器与酒馆后端的边界。

**协议边界：** 官方 Gemini 4 不支持让模型从客户端指定的任意初始回复前缀开始解码。把 assistant 消息移到最后可能产生 HTTP 400；在中间放一条 assistant 消息也不是真预填充。此模式只校正 Lin 原文位置，不声称能解除限制或杜绝截断。

服务商返回 `CONTINUATION` 是另一种情况：上游把同一次生成分段，需能转发原请求和续传凭据的后端处理。扩展只记录是否观察到凭据，不保存值，不把酒馆普通“继续”当成协议续传，不自动发起请求。`STOP`、内容限制或网络中止不等于 `CONTINUATION`。

“原样诊断”和“承接增强（旧版提示）”仍可手动选择；后者只添加普通消息。无需构建。开发验证：Node.js 20+，`npm run check` 与 `npm test`。运行时不依赖 Node.js。

1.2.9 的验证范围见 [VALIDATION-1.2.9.md](VALIDATION-1.2.9.md)。
