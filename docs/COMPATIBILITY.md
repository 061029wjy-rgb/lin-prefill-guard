# v1.4.0 的适用范围

## 选择哪种请求处理

|当前使用情况|插件会做什么|
|---|---|
|Lin 2.9.0，普通回复 / 重新生成 / 滑动|核对两个启用的固定条目、角色、当前类型和实际展开的消息。最后为原 assistant 承接 → 完整 user 确认时，不改它们；两条正好在末尾、彼此倒置且可唯一识别时，仅调回这两个原对象。|
|名称被改过或当前组号未知|优先核对已知版本或条目指纹，再从真实请求验证原文。已确认的全局组采用对应的 100000 或 100001；不能确认组号时要求两组均通过。冲突的版本标识、未来版和脚本重拼为整段的尾部不套用旧规则。|
|Lin 2.9.0，原样诊断、关闭无损承接、继续 / 静默 / 模拟用户 / 未识别类型|不添加辅助区，不改末尾，不调预算。续写优先保留宿主已有的前缀及位置。|
|Lin 2.8.2|沿用 v1.3.0 的原样诊断、承接兼容、Vertex 正文承接和可选已有预算开关；2.9 新实验不在 2.8.2 上执行。测试包括上限开关开启的对照。|
|2.6 等普通旧版|原有增强、取证与手动恢复由原路径处理；不能把本版针对 2.9.0 的声明推广到所有旧版。|
|实际有工具、函数、结构化输出、多候选、多模态、思考签名、缓存内容引用、明确原生前缀或续传凭据|优先保留原始请求，拒绝实验改写。酒馆的 Google 路径打开网页搜索也会在后端生成工具，因此原样放行且不给随机宏抽样。|
|组装后聊天或输入变化、另一插件重建成冲突内容、没有最终发送事件、请求体无法核对|跳过；不算成功提交、不另发请求。接管前后完全一样的规范 JSON 可以重新核验；当宿主的序列化方式无法保证无损时使用原字节。|

2.9.0 的角色权限、反八股、防全知、反翻旧账、摘要、Lin_CoT、角色卡/世界书、用户原话和所有既有组件没有文本替换入口。版本提示和事件日志的哈希不作为移动依据：必须在运行时同时确认唯一性、独立消息、角色、原文和末尾位置。没有凭据就不移动，不能把用户引用的一段指令误当成承接。

## 连接及字段

|酒馆请求|实验可用条件|已知限制|
|---|---|---|
|AI Studio / MakerSuite 与 Vertex 的 `messages`|目标连接和别名明确；纯文本、有有效系统前缀、`use_sysprompt: true`、网页搜索关闭；可添加一条独立 system 消息。|酒馆会在服务端转换为 Google 格式。开着搜索时保留它，面板说明本轮跳过；不会代替用户改设置。|
|自定义 Chat Completions|同样的尾部证据；有系统前缀，且没有声明会再处理请求的自定义参数/头部或后处理；独立 system 消息。|真正的中转商可能再次合并或转换消息；浏览器无法说明其下游行为。|
|能在已核实的酒馆生成 POST 上见到的 `contents` + `systemInstruction.parts` 或 `system_instruction.parts`|同一聊天及模型身份；既有系统段都是纯文本；只增加一个 `{text:…}`，保留原字段拼写。|不拦截向 Google 或任意第三方域名的直接请求。若系统段不存在、不独立，或内容含签名/工具/图片，跳过。|
|Argon / Carbon / Hydrogen / Neon|仅按完整的 `gemini-4-…` 等明确连接标识识别；名称匹配与协议检查分开。|四个标签均有本地结构测试；Neon 尤其不能靠名称认定真实型号。未验证任何别名的上游账户、可用性或路由。|
|真实的原生预填充|已有原生前缀直接放行。|本扩展维护消息式承接，不能给不支持原生前缀的渠道增加此能力。|

## 哪些字节会变化

标准 = 一行格式标识；深度 = 结构化的格式标识；随机宏 = 可选样本。三者均只在一个专用位置产生**一个**模型可见的载体。随机宏关闭时，两个格式档都完全确定。下表是实测普通紧凑 JSON、已排序尾部、短 1 组样本的请求体净增加量；消息序列化、长度或组数变化时，以本轮记录为准。

|格式 / 新随机宏|普通消息：新增 system|Google 原生：新增文本 part|
|---|---:|---:|
|关闭 / 关闭|0 字节|0 字节|
|关闭 / 开启|50 字节|31 字节|
|标准 / 关闭|43 字节|24 字节|
|标准 / 开启|59 字节|40 字节|
|深度 / 关闭|55 字节|36 字节|
|深度 / 开启|79 字节|60 字节|

默认放在系统前缀结束处，可选第一条系统消息/第一段系统内容之后。既有相似标识来源不明时，**不删、不覆盖、不叠加**。同一轮匹配的重复事件或宿主重试复用原样本；插件不发起网络重试。新滑动/重生成可按设置再抽；普通继续不抽。随机源不可用、核对超限（字符串最多 4 × 1024² 个 UTF-16 单元）或身份过期时原样放行。

## 取证与临时复制

- 「规划、提交、发送、HTTP 回应」是四件事；收到 HTTP 回应没有提供 Google 路由证明。窗口内实际净增用 UTF-8 字节数，输入/缓存 token 只用接口提供的数值。
- 后台保存至多 50 次诊断。新路径的报告只保留投递位置、长度、归一化连接、角色顺序、停止/用量统计。请求配对用的数据在内存中；正文、密钥和思考签名不写入 2.9 的日志。
- 被动观察只读取酒馆实际消费的字节，支持取消；观察超出 2 MiB 或 10 分钟会丢弃缓冲，正文仍照常通过。只对一个候选、成功结束、可识别的文本提供「复制本轮已返回文本」；换聊天、关闭开关或清空可使副本失效。
- 工具配对的功能只供隔离验证，不能在真实请求中开启。不把世界书/聊天搬进工具说明，不把工具返回或签名当作正文。
- 其他扩展在本插件之后仍可能处理请求。关闭/卸载会清除自身监听器；若第三方后来又包裹发送函数，则使自己的旧层立即成为直通，避免拆掉对方的钩子。
