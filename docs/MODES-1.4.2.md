# 开工前冻结的能力与边界（1.4.2）
基线是上传 ZIP 对应的 1.4.1；原 ZIP 与可查 git 提交的 85 个跟踪文件逐字一致。用同一个 Node，在不带私人附件时 311/372 通过、61 跳过；提供指定 Lin 2.9.0 时 313/372 通过、59 跳过，两次零失败。

|选择|层与字段|解决什么问题／实际动作|适用边界|对缓存、原文、失败的影响|
|---|---|---|---|---|
|关闭（出厂）|不引入新的请求字段|沿用 1.4.1 所选承接和独立设置|所有旧模式|请求仍与相同设置的基线对比；已经手动打开的旧格式实验不会被升级关闭|
|标准：协商回复格式|浏览器→同源酒馆模型生成 POST 的 HTTP Accept|酒馆依 stream 选 JSON 或 SSE 解析器，默认却未声明接收类型。若接入层按 Accept 选择表示，默认可能返回另一种；本模式显式协商同一种。|仅已关联、已核对尾部和文本结构的 Lin 2.9.0、布尔 stream；现有明确 Accept 优先。|不改模型请求 JSON 或输出上限；HTTP 层可能按 Vary: Accept 区分缓存。接入层可忽略；无法安全设置头时只放行实验接手前的请求，不重发。|
|标准＋Google 网页搜索|在酒馆 messages 中仅对已证实放反的最后两条原承接交换位置；否则 JSON 原字节不动|以前搜索一开连末尾都无法核对。新适配只放行宿主原生搜索开关，另行检查工具、签名、内容类型与请求一致性。|Google 原生酒馆适配器，普通/重生/滑动；搜索回合不加格式标记或随机样本。自定义工具和签名回合完全跳过。|没有新的搜索调用，工具定义、原始文本及顺序正常的历史不变。仅属旧承接的范围扩展，不计作独立新策略。|
|深度（不可选）|无|没有第二种有证据且不动受保护文本的深度机制|所有渠道暂不提供|不偷偷降级到标准，不保留假开关|
|独立随机宏|插件新建的一条 system 消息或一个独立原生系统 part|为人工对照提供样本；沿用 1.4.1 的编号格式，另提供同题重抽复用|与标准开关独立；仅有可证明的插入位置时发送|可能打散提示缓存；无随机源或身份不明时不冒用样本；不能推断路由改变|
|新实验诊断|仅界面|显示本轮关联状态与固定字段，不改变 captureNetwork|可与旧诊断分别启停|复制使用白名单；不包含聊天、URL、密钥、签名、随机样本值|
|旧版高级格式对照|原 shield 键不改|1.4.1 的文本/JSON 标记仍可独立对比|维持原有适用范围|不冒充标准或深度机制|

主动接管工具输出未实现；保留原有被动复制与本地协议样例。浏览器发送、酒馆后端发出、返回格式选对、模型质量、上游路由五项分别验证。
