# 1.4.3：动手前的基线与取舍

基线是上传的 1.4.2 ZIP；包内全部 119 个跟踪文件与提交 7aed2c68a2f633a571dc79c765f27ca374c00828 相同。开发前在同一台机器重跑：403 项单测、344 通过、59 条缺外部材料跳过；真实酒馆原版验收为 24 对字节一致、16 行适配差异、82 个生成 POST。详见 evidence/v143。

1. 拆开旧响应格式协商、旧格式标记与新策略。保留旧键和值，升级不替人开实验。新标准只处理已被证实的本插件辅助标记整段回显：用户主动重试同一题时不再新建那条辅助消息。不删聊天里任何既有文字；普通拒答、半句、过滤、未读完的回包均不符合这个条件。深度不开放。
2. 请求正文的媒体类型（Content-Type）和回复格式（Accept）是两个方向。缺少前者、且能证明为宿主规范 JSON 时，可选补上；不覆盖任何显式类型。只称“请求格式兼容”，不算模型可见机制。
3. 新随机锚用在浏览器到同源酒馆这一跳，作为一次性请求编号，检查可选的同名响应头；不写进提示词。它与旧样本编号可同时开关。回包无对应字段就是“未回传”，不推断远端路由；匹配也不是身份认证。每轮只抽一次，不认领上一轮的回包。
4. 界面明确暂停和重置的字段；原先的两个批量操作放在旧版控制区并保留语义。默认分享仅用枚举和计数；新记录的正文核对散列只在当前页面比较。
5. 两套启用顺序分别核对；比较同一次组装后的输入。文学评测与协议测试分开，受控回显不当成真实模型改善。无凭证不进行收费请求。接收端未报告用量就显示未知；整轮用量不是单个实验的用量。
